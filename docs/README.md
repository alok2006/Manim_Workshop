## Reference material that is generated, not written

Some things in `docs/` are produced by the repository's own tooling, so they
cannot drift away from the code:

| Path | Produced by | Kept honest by |
|:--|:--|:--|
| [gallery/](gallery/) — one still per scene | `scripts/make_gallery.py` | both are regenerated by `make gallery` |
| [../videos/](../videos/) — 17 low-quality previews | `scripts/check_scenes.py --publish videos` | `make videos` |
| the scene tables in [03](03-scene-catalog.md) | hand-written | `tests/test_docs.py` fails if a scene is undocumented |

## Conventions used in these notes

* Commands are shown with the repository root as the working directory.
* `manim` means "the Manim CLI from *your* virtual environment" — activate it
  first (see [01](01-getting-started.md)).
* Code blocks marked `python` are excerpts from `scenes/`; the file and class
  they come from is named just above the block.
* Anything that looks like a claim about Manim's behaviour was checked against
  Manim CE 0.21.0 — the version pinned in `requirements.txt`.
