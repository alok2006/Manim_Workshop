# 04 — Rendering guide

How to turn a scene into a file: qualities, formats, where the output lands, how
caching works, and how to render everything at once.

## Qualities

`-q` takes one letter. Choose the lowest quality that answers your question
while you are iterating — the difference between a 3-second and a 90-second
feedback loop is the whole workshop.

| Flag | Resolution | FPS | Use it for | Typical render time here |
|:--|:--|:--|:--|:--|
| `-ql` | 854×480 | 15 | development, the workshop itself, `videos/` | 2–15 s per scene |
| `-qm` | 1280×720 | 30 | slides, screen-sharing | ~4× `-ql` |
| `-qh` | 1920×1080 | 60 | publishing | ~6–8× `-ql` |
| `-qp` | 2560×1440 | 60 | large screens | ~10× `-ql` |
| `-qk` | 3840×2160 | 60 | the archive copy | ~15× `-ql` |

All 17 scenes together take **under 20 seconds** at `-ql` on a modern laptop
(measured: 17.9 s wall-clock with 6 parallel workers). The same set at `-qh` is
several minutes — render one scene at a time there.

Other useful flags:

| Flag | Effect |
|:--|:--|
| `-a`, `--write_all` | render **every** scene class in the file |
| `-s`, `--save_last_frame` | write a single PNG of the final frame instead of a video |
| `--format gif` | write a GIF (great for chat/PRs, small for these scenes) |
| `--disable_caching` | ignore the cache and re-render everything |
| `--flush_cache` | delete the cached partial movies for this scene |
| `-n 3,7` | render only animations 3–7 (fast iteration on one beat) |
| `--media_dir DIR` | write somewhere other than `./media` |
| `-o name` | change the output file name |
| `--dry_run` | build every frame, write no file (the CLI's "does it run?" switch) |

## Common commands

```bash
# one scene, quickly
manim render -ql scenes/05_parametric_curves.py RoseCurve

# every scene in one file
manim render -ql -a scenes/06_flowers.py

# publishing quality, custom output directory
manim render -qh scenes/07_fourier_epicycle.py FourierEpicycle --media_dir out/

# a GIF for a chat message
manim render -ql --format gif scenes/05_parametric_curves.py SineSnake

# just look at the last frame (no video encoding at all)
manim render -ql -s scenes/06_flowers.py FlowerWithGradient

# iterate on one animation number
manim render -ql -n 2,4 scenes/04_groups_and_rotation.py CircleAndSquareRotating

# run everything, in parallel, with a report
python scripts/check_scenes.py --render --quality l --jobs 6 --json report.json
```

## Where the output goes

```
media/videos/<stage>/<quality>/<SceneName>.mp4
```

For example `media/videos/04_groups_and_rotation/480p15/CircleAndSquareRotating.mp4`.
The `<stage>` directory is the **file name** of the scene module (`04_groups_and_rotation`),
and `<quality>` is named after the vertical resolution and frame rate (`480p15`).

Alongside each video Manim keeps `partial_movie_files/` — one small `.mp4` per
animation. Those are the cache.

## Caching: why the second render is instant

Manim hashes each animation's inputs. If you re-render a scene after changing
only its last play, the earlier animations are reused from
`partial_movie_files/` and the render is nearly instant. This is why
`make render` over the whole workshop is cheap even after an edit.

It can also confuse: if a change does not appear, the cache is the first suspect.

```bash
manim render -ql --disable_caching …      # ignore the cache
manim render -ql --flush_cache …          # delete this scene's cache
rm -rf media/                             # nuke everything (regenerable)
```

`media/` is git-ignored. The curated previews in `videos/` **are** tracked; see
[`videos/README.md`](../videos/README.md).

## Which artefacts are committed, and why

| Path | Tracked | Produced by |
|:--|:--|:--|
| `media/**` | no | every `manim render` (scratch) |
| `videos/*.mp4` | **yes** (2.5 MB) | `make videos` → `scripts/check_scenes.py --render --publish videos` |
| `docs/gallery/*.png` | **yes** | `make gallery` → `scripts/make_gallery.py` |

Both tracked sets are regenerable from source with one command each, and both
are regenerated by CI-adjacent tooling rather than by hand — so they cannot
silently drift from the scenes.

## Verifying instead of rendering

The repository's checker has three levels, cheapest first:

```bash
python scripts/check_scenes.py              # static: parses, names, docstrings   (<1 s)
python scripts/check_scenes.py --dry-run    # executes every scene, writes nothing (~20 s)
python scripts/check_scenes.py --render     # real videos                        (~20 s at -ql)
```

Useful options: `--only RoseCurve,FourierEpicycle`, `--jobs 6`, `--timeout 300`,
`--json report.json`, `--list`.

## Rendering in the notebook

The `%%manim` cell magic accepts the same flags as the CLI:

```python
%%manim -ql --format gif RoseCurve
class RoseCurve(Scene):
    ...
```

The magic is registered when `from manim import *` runs, so execute the imports
cell first. Renders land in the notebook's working directory, not in `media/`.

## Tips that save real time

1. **Develop at `-ql`.** Always. Look at the file, not at your memory of it.
2. **Use `-s`** when you only care about composition — PNG in a fraction of the time.
3. **Use `-n a,b`** to re-render one animation while tuning its timing.
4. **Prefer short `run_time`s** while iterating; put the final pacing back at the end.
5. **Watch the terminal.** Manim prints the exact output path; `File ready at …`
   is the only line that matters.
6. **Fourier epicycles cost what they cost.** `FourierEpicycle` rebuilds 123
   mobjects per frame and is ~4× slower than any other scene here. Lower
   `num_coeffs` while iterating.
